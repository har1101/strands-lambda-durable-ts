# docs/context

作業の進捗、引き継ぎ事項、学びを日付ごとに残すディレクトリです。どのモデルやハーネスで作業するときも、最初にここの最新ファイルを読んでください。

## ファイル

| ファイル | 内容 |
| --- | --- |
| `YYYY-MM-DD-handoff.md` | 現状（リポジトリ、デプロイ、PR、外部への提案）、進捗、未決事項、次の作業、引き継ぎ事項 |
| `YYYY-MM-DD-learnings.md` | その日の作業で得た学び（技術的な事実、落とし穴、判断の理由） |

- 日付は Asia/Tokyo です。同じ日にもう一度作業したときは、その日のファイルを更新します。
- 日本語で書きます。事実、手順、URL、コマンドを具体的に書いてください。
- 最新の handoff が唯一の正です。過去の日付のファイルは履歴なので、編集も削除もしません。

## 新しい handoff に残すもの・落とすもの

新しい日付の handoff は、直前の handoff をもとに作ります。そのファイル単体で現状が分かるようにし、各項目を次の基準で仕分けます。

| 残す | 更新する | 落とす |
| --- | --- | --- |
| まだ成り立つ事実（リポジトリ、リソース ID、URL、手順、コマンド） | 状態が変わった項目（例: 「未デプロイ」→「デプロイ済み」、名前の変更） | 完了した作業の途中経過や、解決した未決事項（結果が必要なら 1 行だけ残す） |
| 未決事項、次の作業、構想 | 手順や前提が変わった箇所 | 置き換えられた手順、古い名前や URL、使われなくなった回避策 |
| 既知の制約、外部の状態（上流の PR や Issue など） | | 一度きりの調査ログ（必要なら learnings に移す） |

learnings は、その日に新しく分かったことだけを書きます。以前の学びが誤りだと分かった場合は、新しいファイルに訂正と理由を書きます。

## 自動化（oh-my-pi）

`.omp/extensions/context-sync.ts` は、omp のメインセッションが終わる直前（`session_stop` イベント）に動きます。`docs/context/` の最後のコミットより新しい作業がある場合、つまり `docs/context/` 以外への新しいコミットか未コミットの変更がある場合は、エージェントに次の作業を依頼します。

1. 上記のファイルを作成または更新する。
2. `docs/context/` だけをコミットして、現在のブランチに push する。

同じ作業状態に対しては 1 回しか依頼しません。サブエージェントでは動きません。

- 無効にする: 環境変数 `OMP_CONTEXT_SYNC=0` を設定します。
- タイムゾーンを変える: 環境変数 `OMP_CONTEXT_SYNC_TZ` を設定します。

omp 以外のハーネス（Claude Code など）で作業したときは、終わる前に同じ手順を手動で実行してください。
